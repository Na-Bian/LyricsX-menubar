# macOS 菜单栏歌词自动收起与切换动画设计

## 背景

LyricsX 当前使用 `MenuBarLyricsEnabled` 同时表达用户是否启用菜单栏歌词，以及界面是否显示歌词。暂停时虽然可以显示“无可用歌词”，但歌词状态项仍占用菜单栏空间；歌词行切换则由单个 `MarqueeLabel` 立即更新，没有过渡。

本次优化只调整 macOS 菜单栏歌词，不改变桌面歌词、歌词窗口、Touch Bar 歌词或 Windows 迁移项目。

## 目标

- 用户启用菜单栏歌词后，播放时显示歌词。
- 暂停、停止或没有活动播放持续 1.5 秒后，收起歌词并显示现有 LyricsX 图标。
- 恢复播放时立即显示最新歌词。
- 自动收起不修改 `MenuBarLyricsEnabled`，菜单项继续保持勾选。
- 歌词文本切换使用约 180 毫秒的交叉淡化。
- 避免切歌、缓冲和快速暂停/恢复造成状态项闪烁。
- 尊重 macOS“减少动态效果”设置。

## 非目标

- 不新增用户可配置的延迟或动画选项。
- 不修改“启用菜单栏歌词”的菜单文案、快捷键或持久化格式。
- 不为桌面歌词、歌词窗口或 Touch Bar 增加同类动画。
- 不改变歌词搜索、匹配、过滤或时间同步算法。
- 不在暂停时移除整个 LyricsX 状态项；仍保留现有应用图标和菜单入口。

## 方案选择

### 采用：控制器内的运行时可见状态

`MenuBarLyricsController` 保留对用户偏好、播放状态和状态项生命周期的所有权。`MenuBarLyricsEnabled` 只表示用户意图；控制器根据播放状态派生当前应该显示歌词还是应用图标。

该方案沿用现有职责边界，改动集中，不会影响其他歌词界面。

### 未采用：自动修改用户偏好

在暂停和播放时直接改写 `MenuBarLyricsEnabled` 虽然代码较少，但会使菜单勾选和快捷键状态反复变化，并覆盖用户的持久选择。

### 未采用：全局显示协调器

建立跨菜单栏、桌面歌词和 Touch Bar 的统一协调器扩展性更强，但当前没有跨界面需求，会扩大改动范围。

## 运行时状态

控制器使用以下输入：

- 用户偏好：`defaults[.menuBarLyricsEnabled]`
- 播放状态：`selectedPlayer.playbackState.isPlaying`
- 当前待执行的暂停收起任务
- 当前歌词文本与显示时长

界面状态只有两种：

1. **歌词状态**：存在 `lyricStatusItem`，移除 `iconStatusItem`。
2. **图标状态**：存在 `iconStatusItem`，移除 `lyricStatusItem`。

`MenuBarLyricsEnabled == false` 时始终进入图标状态，任何播放事件都不得自动恢复歌词。

`MenuBarLyricsEnabled == true` 时：

- 播放开始或恢复：取消待执行的收起任务，并立即进入歌词状态。
- 暂停、停止或无活动播放：创建 1.5 秒延迟任务。
- 延迟到期：再次确认用户仍启用菜单栏歌词且播放器仍未播放，然后进入图标状态。
- 延迟期间恢复播放：取消任务并保持歌词状态。

应用启动时使用播放器当前状态初始化：

- 已播放：直接显示歌词。
- 未播放：直接显示图标，不等待额外 1.5 秒。

所有 `NSStatusItem` 创建、移除、尺寸更新和视图动画都在主线程执行。播放事件可从任意调度队列到达，但只能通过主线程入口改变界面状态。

## 歌词更新与隐藏期间行为

`screenLyrics` 继续保存最新文本和该行显示时长。菜单栏处于图标状态时，歌词搜索和同步仍可更新 `screenLyrics`，但不创建歌词状态项，也不播放动画。

恢复播放时，直接显示 `screenLyrics` 的最新值，不从旧歌词开始过渡。用户重新启用菜单栏歌词时，只有播放器正在播放才立即显示最新歌词；未播放时仍显示应用图标。

以下文本变化都使用相同的交叉淡化：

- 正常歌词行之间切换
- “正在搜索歌词”与歌词之间切换
- “无可用歌词”与其他文本之间切换

相同文本不会重复启动动画。

## 交叉淡化视图

新增 `CrossfadeMarqueeView`，内部叠放两个 `MarqueeLabel`：

- 活动层显示当前文本。
- 备用层接收下一段文本，初始透明度为 0。
- 更新时，活动层在约 180 毫秒内淡出，备用层同时淡入。
- 动画完成后交换两层角色，并清理旧层内容和动画状态。
- 长文本继续使用现有 `MarqueeLabel.setStringValue(_:lineDisplayTime:)` 跑马灯行为。

首次创建歌词状态项、从图标状态恢复歌词，以及视图尺寸变化后的首次渲染均直接显示最新文本，不从空白内容淡入。

若新文本在前一动画完成前到达，视图取消未完成动画，以当前最新可见状态为起点，只过渡到最后一次收到的文本。完成回调必须使用更新序号或等价的失效机制，防止旧回调交换错误的前后层。

系统启用“减少动态效果”时，视图立即替换文本并跳过动画。

## 资源与生命周期

- 控制器只保留一个可取消的暂停收起任务。
- 新的暂停事件替换旧任务。
- 开始播放、用户关闭菜单栏歌词以及控制器销毁时取消任务。
- 移除歌词状态项时停止两个 `MarqueeLabel` 的动画，避免不可见视图继续工作。
- 状态项菜单仍由现有 `setupStatusItemMenu()` 维护，图标状态和歌词状态继续使用同一菜单。

## 测试与验收

将运行时可见性决策提取为不依赖 AppKit 的小型纯状态逻辑，以便覆盖：

1. 启用且正在播放时立即显示歌词。
2. 暂停后先保持歌词，1.5 秒到期后显示图标。
3. 延迟期间恢复播放时取消收起。
4. 用户手动关闭后，后续播放不会自动显示歌词。
5. 应用启动时分别处理正在播放和未播放状态。
6. 多次暂停事件只保留一个有效收起任务。

交叉淡化视图验证：

1. 相同文本不重复动画。
2. 快速连续更新后只显示最新文本。
3. 动画结束后只有一个可见层。
4. “减少动态效果”下立即更新。
5. 长歌词仍能滚动，菜单栏宽度设置仍生效。

手动验收：

1. 播放音乐，确认歌词立即出现。
2. 暂停不足 1.5 秒后恢复，确认歌词状态项不闪烁。
3. 暂停超过 1.5 秒，确认歌词收起且 LyricsX 图标出现，菜单项仍保持勾选。
4. 恢复播放，确认最新歌词立即出现。
5. 手动取消“启用菜单栏歌词”，确认播放状态不再自动恢复歌词。
6. 连续切歌和拖动播放进度，确认没有旧歌词闪回或双层重叠。
7. 开启 macOS“减少动态效果”，确认歌词直接切换。
8. 完成 Debug 和 Release 构建。

## 成功标准

- 暂停持续 1.5 秒后菜单栏歌词稳定收起，恢复播放立即出现。
- 自动行为从不修改 `MenuBarLyricsEnabled`。
- 切歌或短暂缓冲不会导致歌词与图标来回闪烁。
- 正常歌词切换呈现约 180 毫秒的轻柔交叉淡化。
- 快速更新、长歌词和辅助功能设置下没有文本重叠、闪回或持续后台动画。
